### Executive Summary

An urgent end-to-end forensic diagnostic was performed on the real-world accident video `_0RDZgCKPGo_00.mp4` through the deployed **YOLO11-AMF + AMAVE V2 + SASA + SEDE** pipeline. The investigation examined video metadata, active checkpoint integrity, raw YOLO confidence across 8 threshold levels, frame sampling strides ($1, 2, 3$), multi-scale inference resolutions ($640, 960, 1280$), OpenCV/Ultralytics image preprocessing pipelines, and AMAVE 5-stage verification gating.

**Key Technical Findings:**
1. **Model Checkpoint Integrity:** The application is loading the exact deployed frozen model `backend/models/yolov11_amf.pt` (5,458,643 bytes, 320 layers, 2.59M parameters, CUDA active on NVIDIA GeForce RTX 2050). No fallback or stale checkpoints are loaded.
2. **Origin of "31.4% Detection Confidence + Proposals: 0":**
   - The value **31.4% (0.3143)** is the **maximum raw candidate detection confidence** generated by YOLO11-AMF at Frame 174 under production `stride = 2` sampling.
   - The contradictory display of **`Proposals: 0`** was caused by a frontend logic bug in `frontend/script.js` (line 298): `v2CandidateCount.textContent = data.accident_detected ? candidateCount : 0;`. When AMAVE rejected the video, the UI forcibly zeroed out the proposal count while still displaying the raw max candidate confidence.
   - Furthermore, the backend had not been transmitting explicit proposal counts (`candidate_proposals_count`). In reality, YOLO11-AMF produced **16 candidate proposals** across 16 frames ($\text{conf} \ge 0.20$) at `stride = 2`.
3. **The True Accident in Ground Truth:**
   - According to dataset ground truth (`dataset/metadata-real.csv`, line 1053), this video is a **single-vehicle night accident** occurring at **Frame 81 ($t = 5.416$s)** on a New York highway.
   - The accident vehicle is a stationary car disabled on the dark, shadowed **left shoulder/grass** at coordinates $[203, 502, 278, 547]$ (width 75 px, height 45 px, area ratio $0.48\%$).
   - At standard $640 \times 640$ inference, downsampling the $966 \times 720$ night CCTV footage degrades contrast around the dark shoulder car, yielding a raw YOLO confidence of only **$10.15\%$** at Frame 81, which falls below the candidate threshold ($\ge 0.20$).
   - At $1280 \times 1280$ resolution, YOLO11-AMF detects this exact shoulder vehicle at **$28.2\%$ confidence** across consecutive frames 75–89.
4. **Secondary Highway Passing Event (Frames 220–227):**
   - Two speeding vehicles pass in the right lane, sideswiping near the bottom-right camera boundary at Frame 226–227.
   - YOLO11-AMF detects this collision with **$41.72\%$ confidence** at Frame 227.
   - However, under production `stride = 2`, Frame 227 was **skipped** (odd frame parity $227 \pmod 2 = 1$), leaving Frame 174 ($31.43\%$) as the highest sampled detection.
   - AMAVE V2 strictly evaluated this event and rejected it because the vehicles exhibited unidirectional laminar flow ($\text{coherence} = 0.999$) and exited the field of view within 2 frames, failing multi-stage physical persistence and collision kinematic criteria.

### Section 6: Investigation of "31.4% Confidence + Proposals: 0" Inconsistency

#### Root Cause of the UI Display Bug:
1. **Source of 31.4%:**
   - In `backend/api/routes.py`, the backend loops over frames with `stride = 2` and extracts candidate detections with `conf >= CONFIDENCE_THRESHOLD (0.20)`.
   - Frame 174 yielded a candidate bounding box on a vehicle traveling on the adjacent right ramp with confidence $0.3143$ ($31.4\%$).
   - Because Frame 227 ($41.7\%$) was skipped by stride 2, $0.3143$ was the highest confidence detected among all sampled frames.
   - The backend returned `"detection_confidence_pct": "31.4%"`.
2. **Source of Proposals: 0:**
   - In `frontend/script.js` (lines 297–298):
     ```javascript
     const candidateCount = data.total_frames_analyzed ? Math.ceil(data.total_frames_analyzed / 2) : 1;
     v2CandidateCount.textContent = data.accident_detected ? candidateCount : 0;
     ```
   - The frontend author coupled the proposal counter to `data.accident_detected` (which represents the AMAVE final decision).
   - Because AMAVE marked the event as `UNVERIFIED` (`accident_detected: false`), the frontend ternary operator unconditionally set `v2CandidateCount.textContent = 0`.
   - Line 307 set the banner to `"NO CANDIDATE PROPOSALS"`.
   - Line 313 set the pipeline stage badge to `"Proposals: 0"`.
3. **The Disconnect:**
   - The UI displayed:
     - `CANDIDATE PROPOSALS: 0` (from the flawed ternary zeroing logic)
     - `MAX DETECTION CONF: 31.4%` (from the actual YOLO candidate detection)
   - This made it appear that the detector produced 31.4% confidence with zero proposals, which was a reporting contradiction.

#### Applied Correction:
1. **Backend (`backend/api/routes.py`):**
   - Added `candidate_proposals_count: len(all_detections)` (16 at stride=2).
   - Added `candidate_frames_count: sum(1 for _, dets, _ in sampled_frames_data if len(dets) > 0)`.
   - Added `raw_max_detection_confidence: 0.3143`.
2. **Frontend (`frontend/script.js` & `frontend/index.html`):**
   - Decoupled proposal display from `accident_detected`:
     `v2CandidateCount.textContent = data.candidate_proposals_count;`
   - Added dedicated `CANDIDATE PROPOSALS` row to the final summary table.
   - Relabeled `DETECTION CONFIDENCE` to `RAW MAX YOLO CONFIDENCE` to clearly separate detector candidates from AMAVE verification scores.

### Section 7: Threshold Logic Inspection

- **Code Path:** `backend/detection/yolov11_amf.py` (`detect_frame`) and `backend/api/routes.py`.
- **Filtering Logic:** `results = self.model(frame, conf=self.conf_thresh, iou=self.iou_thresh)` where `conf_thresh = CONFIDENCE_THRESHOLD = 0.20`.
- **Detections Below 0.20:**
  - Between $0.10$ and $0.19$, YOLO produces **129 detection frames** (136 total bounding boxes).
  - The ground truth accident at Frame 81 is detected at **$10.15\%$ raw confidence**.
  - At $0.15$, there are 56 detection frames.
  - At $0.20$, there are 33 detection frames.
- **Assessment:** Lowering the production threshold below 0.20 across the entire application would dramatically increase false candidate proposals on highway lane markings and tree silhouettes during night CCTV monitoring. The threshold of 0.20 is scientifically sound; the true limitation on the Frame 81 vehicle is spatial resolution under poor nighttime lighting.
